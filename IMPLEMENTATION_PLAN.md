# Implementation plan

Status as of 2026-10-05. Prototype only.

## Done

- [x] Repository scaffold from Civic Spark's web app: T3 Code chat port, timeline, file explorer, Monaco editor, changes view, theme, mobile CSS, viewport hook.
- [x] Wasmer sandbox adapter (`src/sandbox/wasmer.ts`): bash + Edge.js packages, shell execution with streaming output, filesystem API, IndexedDB persistence of `/workspace`, port exposure.
- [x] In-browser agent runner (`src/agent/runner.ts`) emitting the Civic Spark event protocol; queue, steer, stop, transcript and session persistence.
- [x] Provider sessions: Anthropic (bash + text editor), OpenAI Responses (shell + apply_patch with a V4A patch applier), OpenRouter (function tools). OpenRouter OAuth PKCE sign-in.
- [x] Preview: static server script run by Edge.js inside the sandbox, exposed through the Wasmer service worker on a second origin; Vite plugin serves the host files in dev and emits them in the build.
- [x] Projects home, settings (preview origin, WISP relay), starter template (PROJECT.md only; the agent scaffolds the stack).
- [x] Unit tests: patch parser/applier, tools, changes diffing, runner sequence/queue/stop/failure. Browser smoke on desktop and a Pixel 7 profile in dark mode.

- [x] Preview can load CDN libraries and map tiles (2026-10-06): the SDK service worker forwarded every request into the sandbox and forced `require-corp` on the preview document; both are patched in the Vite plugin, verified by the browser smoke (fetch, dynamic import, classic script) and a live OpenRouter Leaflet turn.
- [x] Runtime recovery: a dead Wasmer scheduler triggers a sandbox rebuild from the in-memory files, with the preview reset. Files are also flushed to IndexedDB after every agent turn and when the tab is hidden.
- [x] Page errors from the preview are captured through an injected reporter and shown in the panel and the agent prompt. grep, sed and ripgrep added; guidance lists what exists.

- [x] Agent preamble ported from Civic Spark's workspace guidance (2026-10-06).
- [x] Page-side tools (2026-10-06): `download` saves URLs into the project through the browser's fetch; `preview` returns screenshots at phone/tablet/desktop sizes, a text outline, HTML or errors from hidden probe frames served by the same sandbox. Covered by unit tests and the browser smoke.

- [x] Hosted on Fly (2026-10-07): `server/main.ts` serves the app and the preview host (port 8443 as the second origin), publishes `/config.json`, mints invite tokens, proxies the free "Sparkbox" provider to OpenRouter with a server key and daily limits, and relays WISP with a TLS-server-name allowlist. Verified locally end to end (`scripts/host-smoke.ts`): invite, proxied model turn, registry fetch and `pnpm add` through the relay, blocked host refused.

- [x] Same-origin WebSockets from preview pages (2026-10-07): the injected bridge shim posts socket operations to the Sparkbox tab, which relays them to a bridge process in the sandbox holding real sockets. Verified by `scripts/ws-smoke.ts` locally and on Fly.
- [x] Vite 7 dev server inside the sandbox (2026-10-07): Edge.js cannot execute WebAssembly or native binaries, so `.sparkbox/vite.mjs` rewrites the installed Vite to use an esbuild client that forwards calls over stdio to esbuild-wasm in the page (plugin hooks are called back in the sandbox, files go through the sandbox filesystem), acorn for Rollup's parser and the asm.js import lexer. Watching is event-driven (exact paths from the page, a workspace diff after each shell command, a ten-second content scan only as a fallback). Verified by `scripts/vite-smoke.ts`: config bundling, TypeScript entry, CSS hot update without reload, React pre-bundling, Fast Refresh with state preserved for page and shell edits.

- [x] Prompt benchmark (2026-10-08): `scripts/benchmark-run.ts` drives the in-page agent through the real UI on the Oak Park transit brief (`docs/benchmark.md`, reports in `docs/benchmark-runs/`). The baseline run never got the app running; the prompt now states what the relay reaches, which native tools do not run, that the Vite launcher appears when the preview starts and that `vite build` cannot run from a shell, that data typed from memory is invented, and when to stop and report. Found and fixed on the way: the preview probe's forced light/dark schemes were inverted by an extra escape level in the bridge script (the browser smoke now asserts on the rendered background), and exports under `artifacts/` triggered dev-server reloads.

- [x] Open relay (2026-10-08): the WISP relay reaches any public host on 80/443 instead of a registry allowlist, because projects need live APIs (CTA refused the Oak Park app). Abuse is made inconvenient rather than impossible: the destination name is resolved on the host and private or internal answers are refused with the connection pinned to the vetted address; the upgrade must carry the app's Origin; the URL holds a one-day relay ticket (`POST /api/relay`, scoped signature) instead of the invite; connections per invite and streams per connection are capped; bytes count against the daily budget. `SPARKBOX_RELAY_ALLOWLIST` restores a named allowlist. The prompt now tells the agent to proxy CORS-blocked APIs through a sandbox server.
- [x] Fetch proxy on the host (2026-10-08): `GET /api/fetch?url=…` fetches a URL for the download tool when the site sends no CORS headers (invite token, GET only, public hosts only including through redirects, 25 MiB cap, the relay's daily byte budget, URLs never logged). The tool tries the browser first and falls back when a host is configured. Unit tests in `tests/fetch-proxy.test.ts`; checked end to end by `scripts/host-smoke.ts`.

- [x] GitHub (2026-10-08): Sign in with GitHub through the host's code exchange (`POST /api/github/token`, `SPARKBOX_GITHUB_CLIENT_ID`/`_SECRET`) or a pasted token; Back up creates a public repository and pushes, then after every agent turn; Publish turns on Pages (branch for static projects, an Actions workflow for Vite ones) and watches the build; Open from GitHub clones a repository as a linked project. Unit tests against a fake API in `tests/github.test.ts`; the browser smoke runs Back up, Publish and Open from GitHub against a faked api.github.com and a local git server.
- [x] Expired GitHub sign-in and the agent's view of backups (2026-10-09): a rejected token (API 401, or a push GitHub refuses) now forgets the sign-in and every place that reports it offers a way back in: a "Sign in to GitHub again" button in the project header, a sign-in button in the Open from GitHub dialog, and messages that name those places. The agent's prompt and github tool now state whether automatic backup is on (so it never offers to push or calls a push pending) and how the last automatic backup went, so a failing backup is reported to the user once instead of silently.
- [x] Invite first, and the GitHub popup (2026-10-09): a fresh browser could open a GitHub project and find the preview unable to install packages, because the invite (entered only for the free agent) also unlocks the relay. When `/config.json` says the host hands out invites, the app now asks for the code before showing projects, and again when the token's expiry passes or the relay answers 401; "Forget invite" moved from the Agent panel to Settings. Separately, Sign in with GitHub reported "window was closed" after succeeding in a fresh browser: under COOP the opener's `popup.closed` reads true once the popup reaches github.com, so the old watcher gave up at once (a browser that already held a token resolved with it and hid the bug). The popup now writes its outcome to localStorage and the opener waits for that. Unit tests in `tests/github-login.test.ts` and `tests/invite.test.ts`; the browser smoke passes the gate with a faked invite endpoint.
- [x] Context compaction (2026-10-08): the host sets a context limit (`SPARKBOX_CONTEXT_LIMIT`, 80,000 tokens on Fly, published in `/config.json`; a deployment option for cost, not a user setting); when the last prompt exceeded it, the runner folds the oldest half of the turns into a model-written summary (each provider session summarizes in its own message format and reports prompt tokens from usage, with an estimate after a reload) before and after a turn, and posts a status line. Anthropic's server-side compaction does not cover Haiku and is not reachable through OpenRouter's chat API, which the free agent uses. Corner cases: older screenshots (all but two) and earlier turns' tool results are trimmed first without a model call, also mid-turn when a tool loop passes the limit; folding repeats up to three times; the summary budget scales with what was folded (300 to 1,500 words). Unit tests in `tests/compaction.test.ts`. Live-checked on 2026-10-09 with Haiku 5.5 through the worktree host at an 8,000-token limit, which found three bugs: the OpenRouter screenshot follow-up user message counted as a turn, status events were not rendered in the timeline, and the summary request came back empty because the model's reasoning used the whole output budget (the prompt's word count sets the length and the output cap is a generous runaway guard).
- [x] Build scripts and the Pages workflow (2026-10-08, from an agent's field report): `npm install -g pnpm` on the runner gave pnpm 12, which fails outright on esbuild's ignored postinstall; the workflow now pins pnpm 10 and installs with `--ignore-scripts`, which is also forced in the sandbox (`npm_config_ignore_scripts`, since a postinstall there fails with spawn ENOSYS), and a Sparkbox-written workflow is refreshed on the next publish. The git command refuses force pushes, keeps HEAD on its branch for `reset --hard`, and explains a detached HEAD; `.scratch/` and `*.log` are ignored by default; the prompt says never to pipe git or pnpm, to verify pushes with git fetch and git log origin/main, and never to rm -rf node_modules. Verified against pnpm 12 locally (install plus vite build) and in the sandbox (pnpm run and pnpm add with scripts ignored).
- [x] Release-age policy (2026-10-08): the Pages build failed with ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION because the sandbox resolved same-day releases of browserslist's data packages; the sandbox now sets `npm_config_minimum_release_age=1440` for every command, the preview's install deletes and re-resolves a lockfile that trips the policy, and the agent is told never to lower it. Verified in the sandbox: `pnpm add browserslist` picks the day-old versions the runner accepts.
- [x] Runtime data on Pages (2026-10-09, from an agent's field report): a Vite app fetched `data/…json`, which the preview's dev server serves but the build leaves out, so the published site got a 404. The prompt now puts files the page fetches in `public/` (fetched with `import.meta.env.BASE_URL`) and keeps `data/` for downloads and SOURCES.md; the Pages workflow runs a check after the build that fails on quoted paths in `dist/` naming a project file the site lacks, or starting at the domain root. Verified against a real Vite 7 build (both `${BASE_URL}data/x.json` and `BASE_URL + "…"` fold to `/<repo>/data/x.json`). Not done: running the preview under the Pages base path, since the dev server would still serve `data/` and the check covers root paths.
- [x] Preview installs missing dependencies (2026-10-08): a project whose `package.json` declares packages that are not in `node_modules` gets `pnpm install --ignore-scripts` run by the preview before its command, with an "Installing dependencies…" state and the output in Logs; without a relay the panel and the agent are told the packages cannot be reinstalled. Verified against the worktree stack with a relay (`left-pad` installed in 4 s) and in the browser smoke without one.
- [x] git in every project (2026-10-08): isomorphic-git runs in the page over an IndexedDB-persisted object store and the sandbox working tree (`src/git/`); the sandbox's `git` command is a shim that reaches the page through a bridge process (`src/sandbox/git-bridge-script.ts`, `src/git/bridge.ts`); pushes go through the host's git relay (`server/git-proxy.ts`) with the token added in the page. - [x] Sandbox hangs (2026-10-08): the cause is an exception that escapes the guest's JavaScript runtime (for example Rollup's native loader during a raw `vite build`) and crashes the SDK worker; the SDK closes its pool and every later spawn hangs instead of failing, so the dead-runtime recovery never ran. Node's own options cannot intercept it (the rejection reaches the worker before Node's handlers), so `vite.config.ts` patches the SDK worker in dev and build to log guest rejections and let the process continue; a raw `vite build`, a script whose fetch rejects, and a rejection inside the Vite dev server no longer touch the runtime. As a second line, every spawn and wait has a deadline (`src/sandbox/deadline.ts`), a page error triggers a probe, and a hang rebuilds the runtime and tells the agent to reinstall dependencies and restart the preview. `scripts/vite-smoke.ts` checks the prevention end to end.
- [x] Edits lost on reload (2026-10-08): persistence read every file from the sandbox worker before writing IndexedDB, so the save started on `pagehide` never finished and only the debounced save counted. The sandbox now keeps a page-side mirror of the workspace (updated by writes, by the diff after each command, and by a scan before each save while a server runs), the IndexedDB connection stays open, and the hidden/unload save is issued synchronously from the mirror; transactions resolve on commit. The preview runs commands under `.sparkbox/supervise.mjs`, which records child Node pids through a `NODE_OPTIONS` preload and kills them on Stop (the runtime has no process groups and killing a shell leaves its background jobs running). The preview reports a missing `node_modules` after a reload and the prompt tells the agent to reinstall rather than debug. The browser smoke reloads right after an edit and stops a compound preview command, checking both ports.
