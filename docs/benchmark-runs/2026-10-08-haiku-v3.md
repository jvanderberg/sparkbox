Same driver, brief, model and key handling as [the baseline](2026-10-08-haiku.md) and [run 2](2026-10-08-haiku-v2.md). ## Scoring against the reference

**Data correctness: the best of the three Sparkbox runs, and the only one with real bus geometry.** After the CTA and Metra GTFS downloads failed on CORS, the agent searched the Socrata catalog, found the Chicago Data Portal's L-stops dataset (same as the reference, coordinates identical) and its "CTA - Bus Routes" GeoJSON, clipped both to an Oak Park bounding box with small Node scripts, and fetched the Metra station from Overpass with its `ref:metra` tag. `data/SOURCES.md` has URL, publisher, retrieval date, filter and trimmed-file name per source, and a "not yet included" list. Nothing is typed from memory and nothing is labeled approximate. Gaps: no Green or Blue alignments, no Pace (the catalog search found nothing and Overpass returned no Pace relations), two extra bus routes kept because they touch the bounding box, and no arrivals at all.

**Requirements 2 and 5 are not met.** There is no "Next arrivals" panel, no adapter with snapshot and live implementations, no README with the endpoints, no snapshot badge or last-updated indicator. The brief put the key in the chat message; the agent never wrote `.env.local` and its sources file says "requires a CTA API key, no key is stored in the project". The baseline and run 2 both stored and tested the key. Model behaviour, not prompt: the brief's instructions were in context the whole time.

**Mobile rules and both schemes: good for what exists.** Phone: map on top, scrolling station list below, header with the name and a bus-routes checkbox; no overflow in the text outline; dark scheme follows the system with dark panels (`2026-10-08-haiku-v3-*.jpg`). The station list rows are about 44 px. Not verified at 360 px (stated by the agent).

**Honest reporting: good per turn, no final summary.** Each turn ended with what changed, what the preview showed and what remains blocked, including a stale page error it could not clear. Because the driver's follow-ups kept the conversation going, there is no single final report.

**Build cleanliness:** tsc clean after every change. No Tailwind, no shadcn-style components, no Biome (nothing installed beyond React, Leaflet, Vite 7 and TypeScript 5).

**Tooling and framework behaviour: clean.**

- Installs: two pnpm commands (runtime, then Vite 7 with the launcher packages and TypeScript 5), both up front, no later adds, no hangs.
- Preview configured right after the first type-check; "errors" called before every screenshot round and again after each edit; phone, desktop and forced-dark phone screenshots.
- No shell builds, no `npx`, no `timeout`; `du` and `cmp` were tried once each and are absent.
- Scratch files under `.scratch/` as the prompt now asks; the 1.9 MB bus GeoJSON was deleted after clipping.
- No loops: each failed source was tried at most twice, then recorded.

## Environment versus model or prompt

Environment: CTA and Metra GTFS blocked by CORS; Overpass 504 on one retry; the empty first completion from the provider.

Prompt: the data rule worked (real sources, no invented coordinates). The prompt says nothing about pacing a long brief, and this run shows the cost: with data quality now taking priority, the model spent its turns on sources and never built the arrivals half of the app. A generic line about covering every numbered requirement at least minimally before polishing one of them is the next candidate, but it is not in this series because it was not tested.

Model: ignoring the key in the brief; the thin UI; two extra bus routes; per-turn status reports instead of a final one.
