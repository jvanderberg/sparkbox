# Benchmark run: Haiku 5.5 through OpenRouter, baseline prompt (2026-10-08)

Driver: `scripts/benchmark-run.ts` (brief in `scripts/benchmark-brief.md`). Provider OpenRouter, model `anthropic/claude-haiku-5.5` (the free-agent model friends get). The CTA key was pasted into the chat message as the brief does; it is redacted from every artifact. Prompt: `src/agent/system-prompt.ts` at commit 9de3497 (before the changes in this series).

Raw artifacts (git-ignored): `artifacts/benchmark/2026-10-08-haiku/` (transcript JSON and Markdown, chat DOM, preview tool output, screenshots, summary). An earlier attempt with the first version of the driver (`2026-10-08-haiku-aborted.log`) was lost when the driver wedged on the sandbox; it had reached the same `vite build` hang at 73 tool calls and 51 minutes, and is counted in the spend below.

## Outcome

No working app. Four turns, every one stopped by the driver after ten minutes without tool progress; the page had to be reloaded three times because Stop did not end the turn. The preview was never configured, so the preview tool rendered the built-in static server's view of `index.html`, which fails to load `/src/main.tsx` as a module: a blank page in all four screenshots (`2026-10-08-haiku-{phone,desktop}-{light,dark}.jpg`).

## Scoring against the reference

**Data correctness: good, within what the environment allowed.** Stations came from the Chicago Data Portal L-stops dataset with map IDs, platform stop IDs and coordinates that match the reference to six decimals. The Metra station came from Nominatim (building centroid, labeled approximate). `data/SOURCES.md` lists each source with URL, date, filter and a retrieved/not-retrieved status. The agent first wrote straight-line "approximate" bus corridors, then deleted them in the next step because the guidance forbids invented records, leaving `path: []` with "not verified" labels. Arrivals are a hand-written sample file whose top-level field reads "SAMPLE DATA - not live CTA predictions", and in turn 3 the header badge was changed to say "Sample data" rather than "Snapshot". No invented live data. Gaps versus the reference: no rail alignments beyond straight segments between stations, no bus geometry or stops, no Pace data, no real arrivals.

**Mobile rules and both schemes: not assessable.** The app never rendered. From the source in the transcript: `viewport-fit=cover`, `color-scheme: light dark`, Tailwind `darkMode: "media"`, a phone bottom panel and desktop sidebar in `App.tsx`. Unverified.

**Honest reporting: good.** Every blocked fetch was named with its cause (ECONNRESET from Node, CORS from the browser, 504 from Overpass). The agent did not claim the key worked. It never reached a final report, so the "what is verified" summary does not exist.

**Build cleanliness: partial.** `tsc` passed once TypeScript 5.9 was in place. Biome and the production build were never run successfully (see below).

**Tooling and framework behaviour: the run failed here.**

- Install choices were sensible: Vite 7 with the documented launcher dependencies, Tailwind v3 through PostCSS because "Tailwind v4 and Lightning CSS need native code", hand-written shadcn-style primitives because the shadcn CLI needs its registry. It also installed `@biomejs/biome`, which has no binary for this platform, and later `@biomejs/wasm-nodejs`, then spent a turn exploring its low-level Workspace API before giving up.
- `pnpm add -D typescript` resolved to TypeScript 7.0.2, whose `tsc` needs `@typescript/typescript-wasi-wasm32`; eight tool calls went into pinning 5.9.3, complicated by a half-deleted `node_modules/typescript` and files under `/tmp` that disappeared between commands.
- Wrong or missing commands: `npx` and `timeout` do not exist; `npm` is a pnpm shim that rejected `--no-audit`. The agent recovered from each in one step.
- **Preview configuration: never done.** The agent looked for `.sparkbox/vite.mjs`, found it absent (it is written when the preview starts), and deferred the preview "until the code is in place". It never called the preview tool with `configure`, `status` or `screenshot`. All verification was attempted through shell commands instead.
- **`vite build` from the shell:** attempted in turns 2, 3 and 4. It exits 1 with no output, and the next shell command then hangs; Stop does not end the turn. The agent could not know that the launcher's esbuild bridge belongs only to the preview process.
- Loops and stalls: the four turns stalled on the same cause three times. After each reload the model's memory reverted to the end of turn 1 (sessions are persisted only when a turn ends), so turns 3 and 4 each began with "Picking up from where the install stopped" and re-discovered the `src/` tree it had itself written, at one point believing it had overwritten someone else's files.

## Environment versus model or prompt

Environment (not the model's fault):

- The relay only reaches package registries and CDNs. Node fetches to `lapi.transitchicago.com` reset; the browser download of the same URL is blocked by CORS. The CTA GTFS zip is CORS-blocked. Overpass returned 504 twice (load on the public endpoint) and the kumi mirror failed in the browser.
- A failed `vite build` leaves the sandbox unable to run the next command, Stop does not recover it, and a reload drops `node_modules` and the unsaved session state. See the hang check below.
- `npx`, `timeout` and GNU `find` are missing; `/tmp` did not survive the runtime rebuilds.
- Biome and TypeScript 6+ ship native or WASI binaries that do not run here.

Prompt (fixable with generic guidance):

- Nothing told the agent that `vite build` cannot run from a shell, that the launcher appears only after the preview starts, or that the preview tool is the way to run the dev server. It had the right rule ("use the preview tool to check your work") but followed the brief's "run Biome, tsc and the Vite build" through the shell first and never got past it.
- Nothing told it which native tools are unavailable (Biome, Tailwind v4, TypeScript 6+), so it discovered each one by failing, and the default stack line still names Biome.
- Nothing said the relay reaches only registries and CDNs, so ten tool calls went into probing the CTA host from Node three different ways.
- No stop rule for a command that produces no output and a hang that follows; the agent retried the same build in three turns.

Model:

- Writing invented bus corridors before deleting them; the confusion after reloads was amplified by the session revert but the model also did not re-read `BUILD_LOG.md` (it never wrote one).
- Treating Biome's WASM package as worth a turn of exploration.

## Hang check

Reproduced outside the benchmark with a throwaway Playwright script against a fresh project (git-ignored), using the page's `sparkboxExec` hook:

| Command | Result |
| --- | --- |
| `echo ok` | returns in 0.1 s |
| `node -e "setInterval(()=>{},1000)"` | killed at the 180 s timeout, exit 137; the next `echo` returns at once |
| `pnpm add -D vite@7 acorn es-module-lexer@1 --ignore-scripts` | 6 s through the relay |
| `node node_modules/vite/bin/vite.js build` | exit 1 after 0.6 s with no output |
| `echo ok4` afterwards | never returns (gave up after 60 s) |

So the timeout mechanism works for an ordinary hung process, but a failed Vite build (its esbuild package tries to start a native binary) leaves the runtime unable to run anything else, and the recovery path for a dead scheduler does not trigger. That is a Sparkbox bug independent of the prompt; the prompt change only stops agents from walking into it.
