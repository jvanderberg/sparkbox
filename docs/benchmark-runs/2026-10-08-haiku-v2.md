Same driver, brief, model and key handling as [the baseline run](2026-10-08-haiku.md). Prompt: `src/agent/system-prompt.ts` with the first revision from this series (relay scope, native binaries, no production build, launcher written by the preview, verify through the preview tool, stop rule). Raw artifacts (git-ignored): `artifacts/benchmark/2026-10-08-haiku-v2/`.

A first attempt with this prompt (`…-v2a/`) finished in one turn of 11 minutes and $0.08 with the app running, but the driver's file export tripped a Vite full reload (its exported `tsconfig.json` sat inside the dev server's root), which destroyed the page before the screenshots were taken. ## Scoring against the reference

**Data correctness: worse than the baseline.** Only three downloads were tried (CTA GTFS zip: CORS; Overpass: 504; the kumi mirror: CORS) and the Chicago Data Portal, which the baseline found and which allows cross-origin reads, was never attempted. Station coordinates were "typed from general knowledge" and labeled approximate; only Harlem/Lake has a map ID (from the brief's example) and no stop IDs exist. Bus corridors and rail alignments are straight-line placeholders. `data/SOURCES.md` records every attempt with its failure and lists the next steps to replace the data, and nothing is presented as live. The arrivals file is labeled "SAMPLE DATA - not live" in both the badge and the panel, with a sample timestamp of 2025-01-01. Honest, but labeled approximations of coordinates are still invented data; the baseline deleted its own invented corridors, this run kept them.

**Mobile rules and both schemes: mostly good, with one tool-side caveat.** Phone 390×844 and desktop 1280×800 screenshots (`2026-10-08-haiku-v2-*.jpg`): header with name, snapshot badge and "Checked" time; map with Leaflet and OpenStreetMap attribution; Arrivals/Routes tabs; bottom panel on the phone and a sidebar on desktop; no horizontal overflow in the text outline; 44 px tab and station buttons. Dark scheme darkens the tiles with a CSS filter. Caveat: the files named light show the dark rendering and vice versa. That is not the app: the preview probe's scheme forcing was inverted by an escaping bug in the injected bridge script (its `prefers-color-scheme` regex never matched, so `@media (prefers-color-scheme: dark)` rules were enabled under forced light and disabled under forced dark, and the `matchMedia` patch fell through to the system setting). Fixed in `src/sandbox/bridge-script.ts` after this run and verified with `scripts/preview-tool-check.ts`. The agent took both schemes and reported "dark scheme renders with darkened tiles"; it was shown the wrong one and could not have known.

**Honest reporting: good.** The final message separates verified (preview screenshots, no errors, tsc) from unverified (key, arrivals, Biome, production build, tablet and keyboard) and known gaps (approximate coordinates, no Pace geometry, plugin-react removed, proxy needed and why `VITE_` variables must not hold the key).

**Build cleanliness: tsc clean.** Biome installed but cannot run (reported). Production build not attempted, with the reason given.

**Tooling and framework behaviour: large improvement.**

- Installs: three pnpm commands up front (runtime deps; Vite 7, plugin-react, acorn, es-module-lexer, TypeScript 5, Tailwind v3, PostCSS; Biome), then two small adds later. The second small add (`@radix-ui/react-slot`, at the end of a 12 KB heredoc command) hung past its 120 s timeout and cost the first turn. Same failure as the baseline's `class-variance-authority` add.
- Preview configured with the documented command before any screenshot, and used for errors, screenshots and text outlines (15 calls). No shell build attempts, no hangs from them, no reloads.
- `@vitejs/plugin-react` resolved to v6, which imports `vite/internal` and fails under the launcher; v5 was installed but the restart still failed (the previous failure was cached in the preview process), so the agent removed the plugin and used Vite's built-in JSX transform, losing Fast Refresh. Documented in the build log.
- `npx` and `timeout` were still tried once each in the first commands.
- No loops: each blocker was attempted at most twice, then recorded.

## Environment versus model or prompt

Environment: the CTA host and GTFS zip (relay allowlist and CORS), Overpass load, the `pnpm add` hang past its timeout, the inverted scheme probe (now fixed), plugin-react 6 not loading under the launcher.

Prompt (addressed in revision 2, tested in run 3): the install command should pin `@vitejs/plugin-react@5`; installs should be decided up front and run as one command per group to reduce exposure to the hang; data typed from memory should count as invented even when labeled approximate, and one alternative source that allows cross-origin reads should be tried before giving up.

Model: not trying an open-data portal when the primary sources failed; a 2025 sample date in a 2026 sandbox; the first turn's giant single command.
